# Renato
## “Happy Vibe Coding Birthday” (Pixel Platform Game Art for Renato)

Preview: [https://htmlpreview.github.io/?https://github.com/jotafeldmann/art/blob/main/renato/renato.html](https://htmlpreview.github.io/?https://github.com/jotafeldmann/art/blob/main/renato/renato.html)

1. Open the `index.html` first  
2. Run it directly in your local browser  
3. Play until you reach the gift at the end

**Inspiration**  
These days, we can vibe code almost anything: tools, games, interfaces, little worlds, strange experiments, polished prototypes in a single sitting. So the question becomes less *can we build it?* and more *what should we build, and for whom?*

This piece starts from that impulse. If code can now become almost anything, why should it only be used for productivity, optimization, or public performance? Why not use it for play, for affection, for friendship, for birthdays, for people we love?

Instead of a generic birthday message, this work turns code into a small act of care: a playful world, a character, a level, a reward. Not just something to look at, but something to move through. A greeting that is not merely shown, but played.

**Author:** Jorge Feldmann  
**Date:** March 19, 2026  

## Overview

This piece is a small browser game built as a single `index.html`, where Renato appears not as a photograph pasted into motion, but as a character reinterpreted in pixel art and placed inside a simple side-scrolling platformer.

The work draws from the language of classic platform games: running, jumping, collecting objects, and reaching a final reward. But instead of a generic avatar, the central figure is a stylized, animated version of Renato, transformed into playable character design.

The result is both game and birthday gift: a short interactive journey whose final gesture is the encounter with the present itself.

## Trust, play, and the act of opening the file

A local HTML file with embedded JavaScript is not just an image or a message. Opening it means launching a small executable environment: logic, animation, physics, collision, and rendering all come alive inside the browser.

That makes the act of opening this piece a small pact between author and viewer:

- Trust, because you are running a handmade program rather than simply looking at a finished surface.
- Play, because meaning only completes itself when the work is interacted with.
- Recognition, because the person being celebrated becomes the very subject of the system.

This matters to the artwork. The birthday message is not external to the piece; it is reached through movement. The browser becomes stage, console, canvas, and toy all at once.

## Why this is code as art

### 1) The artwork is not only the image, but the behavior

A still portrait could represent Renato, but this piece goes further: it gives him motion, rhythm, and response. The animation is not decoration; it is the medium itself. The character exists through jump arcs, velocity, gravity, and collision.

Here, behavior is form.

### 2) Portrait becomes avatar

The original visual reference is translated into a pixel character. This transformation is essential: the work does not reproduce a face literally, but interprets it through the visual grammar of games.

That shift turns likeness into playability. Renato is not merely depicted; he becomes controllable.

### 3) The code is both engine and composition

The same codebase handles:

- character drawing
- animation timing
- world layout
- collision rules
- collectible objects
- win condition

This dual role is central to the piece’s artistic quality. The code does not sit behind the work as invisible infrastructure; it is the structure of the work itself. Logic becomes composition.

### 4) Vibe coding becomes intimate instead of instrumental

Much of contemporary code culture is oriented toward speed, output, scale, and usefulness. This piece proposes something smaller and more personal: code as gesture, code as gift, code as affection.

If we now have the ability to quickly create playful systems, strange interfaces, tiny worlds, and living images, then maybe some of that energy should be spent on delight rather than efficiency. On making something unnecessary in the best possible sense: something made for one person, because they matter.

### 5) The final reward is narrative, not utility

The present at the end of the level is mechanically simple, but symbolically loaded. Reaching it completes more than a task. It closes the ritual of the gift.

Progress becomes message.

## The process

1. A visual reference of Renato is observed and translated into simplified pixel-art features.
2. The character is rebuilt as a stylized sprite suitable for a platform game.
3. A small side-scrolling level is authored inside a single HTML file with all JavaScript embedded.
4. Movement, jump physics, collision, collectibles, and level completion are implemented directly in the browser.
5. The player guides Renato through the stage in the language of classic platform games.
6. Upon reaching the gift, the piece resolves as birthday greeting, playful portrait, and interactive artwork at once.

## Objective

Celebrate Renato not with a static card, but with a living, playable miniature world in which he becomes both hero and artwork.
